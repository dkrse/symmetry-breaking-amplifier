# Multiplicative amplification of position in social hierarchies

Code and data for the manuscript *Multiplicative amplification of position in
social hierarchies: identifiable dynamics and an unidentifiable seed*
(Physica A, manuscript PHYSA-263058, revision 1).

The repository contains all analysis scripts (`scripts/`), the bundled Music Lab
dataset, and a single-command runner that reproduces every figure and every
number reported in the paper.

## Summary of the paper

The paper asks what the trajectory of a hierarchy (positions tracked over time)
can and cannot identify about the process that generated it. It works within a
minimal multiplicative model of positional amplification with a saturating
feedback and a dominance-triggered reset. The model and the multiplicative
machinery are standard; the contribution is the identification boundary.

**Identifiable: the dynamics.** Whether the process amplifies (`g > 0`) or only
diffuses (`g = 0`) leaves signatures in the trajectory.

1. Without feedback the process is a martingale; amplification is necessary for
   a persistent, heavy-tailed order (Prop. 2).
2. With a per-unit ceiling, the dispersion generated by amplification is
   non-monotone in the gain. The dispersion-maximising gain falls with the
   horizon as `g* ~ T^-0.56 +/- 0.02` (`optimal_gain_fit.py`); the mean-field
   estimate `g* ~ 1/T` gives the direction but not the exponent.
3. In the saturated regime the stationary tail index has the closed form
   `mu = (-c + sqrt(c^2 - 2 sigma^2 ln(1-p_hi))) / sigma^2`,
   `c = ln(1 + g theta S*)`, which reduces to `mu ~ -ln(1-p_hi)/c` when
   `mu sigma^2 << c`. A Hill estimate on the full nonlinear dynamics agrees to a
   mean error of 3.1% over the twelve grid cells with `mu <~ 2`
   (`kesten_tail.py`). The result applies to maintained, revocable statuses, not
   to ceiling-free tokens.
4. Under diffusion, early-lead persistence `rho(tau)` follows `sqrt(tau)`
   (Pearson) or `(6/pi) arcsin(sqrt(tau)/2)` (rank). An excess over this law is
   not diagnostic of amplification: a population whose members differ in a
   persistent trait reproduces it at zero gain, and sweeping `Var(a)` over four
   decades moves `tau90` from `0.79` to `0.005`, covering the whole range of the
   amplifier and of the preferential-attachment null. What identifies
   amplification is a contrast within one system: early-lead persistence drops
   under revocation.

**Not identifiable: the seed.** Capability `k` and position `p` enter the
amplifier through one channel, `a = k + p`. The persistent input `a` is
recovered from the trajectory, but its decomposition is not: two parameter
families induce the same distribution over observables, so no consistent
estimator exists and more data do not help (Prop. 3). An inherited head start
and an early random draw enter in the same way. An exogenous estimate of
capability turns the decomposition into a measurable manufactured share
`R = 1 - corr^2(final order, k_hat)`, an upper bound on the share of the order
generated by amplification.

**Empirical results.**

- Wikipedia adminship elections: revocable (net support) and non-revocable
  (support-only) readings of the same votes differ in early-lead persistence by
  `0.11` at `tau = 0.1` (95% bootstrap CI `[0.09, 0.13]`); `tau90 = 0.375`
  against `0.10`. A heterogeneity placebo accounts for just under a third of the
  gap.
- GitHub stars: strong early-lead persistence (`tau90 = 0.5`), below a fitted
  preferential-attachment null (`tau90 = 0.02`); reported as a free-token case,
  not compared with Wikipedia directly.
- Music Lab: the correlation of success with quality falls from `0.765` to
  `0.651` between the weak- and strong-signal experiments (one-sided
  `p = 1.5e-3`); the two experiments also differ in presentation, which the
  paper reports as a confound.
- Online chess (Lichess 2013): a cohort with near-equal entry ratings shows
  every trajectory signature of generated order, yet a convergent skill estimate
  six months later gives `R ~ 0.38` (95% CI `[0.26, 0.51]`), so at least about
  62% of the order is revealed skill.

**Removed in revision 1.** The original submission reported a cross-domain
`rho(tau/tau90)` curve-collapse test (simulation plus three real free-token
domains, including a Crunchbase startup cohort). Its real-data half was
inconclusive, so it was removed from the revised manuscript. The code and data
remain here; see the paper-to-repository map for what the revised paper uses.

## Reproduce

```bash
./run_all.sh            # offline reproduction: figures and every reported number
./run_all.sh --power    # + power analysis, g*(T) fit, tail-index check
./run_all.sh --online   # + Wikipedia RfA and GitHub analyses
./run_all.sh --lichess  # + online-chess example
./run_all.sh --power --online --lichess   # everything
./run_all.sh --help
```

`run_all.sh` creates a local virtual environment (`.venv`) from
`requirements.txt` (numpy, scipy, matplotlib, requests) and runs the analyses.
The default and `--power` tiers are offline; the network is used only for the
one-off `pip install`. The `--lichess` tier needs the `zstd` CLI on PATH
(`apt install zstd`) and is skipped if it is absent.

### Run time

Measured on one 8-core workstation without GPU. Each run prints its own
per-script timing.

| Tier | Wall-clock | Dominated by |
|---|---|---|
| default (offline) | about 30 s | ten scripts, each under 10 s |
| `--power` | about 22 min | `kesten_tail.py` 15 min, `power_analysis.py` 5.5 min |
| `--online` | about 30 s | Wikipedia RfA 28 s, plus GitHub API if the cache is cold |
| `--lichess` | about 20 s | once the dumps are cached |
| everything | about 23 min | |

First-run costs not in the table: the `pip install` (one to two minutes) and,
for `--lichess`, streaming about 150 MB of Lichess dumps, cached afterwards
under `scripts/data/lichess/`. With `GITHUB_TOKEN` set and a cold cache the
GitHub arm re-queries the API and is limited by the API rate.

## Real-data analyses (`--online`)

- `wiki_rfa_toppling.py` measures both arms of the revocation contrast inside
  the Wikipedia Requests-for-Adminship dataset (SNAP `wiki-RfA`, 2269 elections
  with at least 25 signed votes): running net support as the revocable position,
  the support-only cumulative count as the free-token reference.
  `run_all.sh --online` passes `--bootstrap 2000`, resampling elections for a
  95% CI on the contrast (gap at `tau = 0.1`: `0.11 [0.09, 0.13]`; `tau90`
  difference `0.275` in the full sample, bootstrap mean `0.245 [0.20, 0.28]`).
  It also runs the heterogeneity placebo (i.i.d. votes at zero gain, candidates
  carrying the empirical spread of final support shares), which returns a mean
  early gap of `+0.033` against `+0.115` in the data.
- `github_earlylead.py` measures early-lead persistence for a cohort of 295
  repositories created in 2019 Q1 (final stars 80 to 3000) over 24 months, from
  star timestamps read through the GitHub GraphQL API.

### GitHub token

The GitHub API allows 60 requests per hour unauthenticated and 5000 with a
token, so `github_earlylead.py` needs a personal access token (never committed):

1. Go to <https://github.com/settings/tokens>.
2. Create a fine-grained token with *Repository access: Public repositories
   (read-only)*, or a classic token with no scopes ticked.
3. Export it before running:
   ```bash
   export GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
   ./run_all.sh --online          # the GitHub arm is skipped if the variable is unset
   ```

API responses are cached under `scripts/data/github_cache/`. The Wikipedia arm
needs no token; it downloads one public SNAP file once.

## Online-chess example (`--lichess`)

`lichess_worked_example.py` streams three monthly
[Lichess open-database](https://database.lichess.org) dumps (2013-01 as the
entry cohort; 2013-07 and 2013-12 as the +6- and +12-month skill estimates),
forms a near-equal entry cohort (ratings 1480 to 1520, at least 30 games in the
month) and a heterogeneous control (1000 to 2200), and prints Table 4 of the
paper.

- Trajectory signatures: the month-end order is uncorrelated with the entry
  rating (`-0.05`, against `+0.60` in the control) and locks in faster than the
  `sqrt(tau)` law (excess up to `+0.28`).
- Entry-band diagnostic: the cohort's month-end spread (s.d. `213`) equals the
  whole population's (`212`), so the narrow band equalised the rating estimate,
  not capability, and the cohort is an instance of the heterogeneous-drift null.
- Convergent channel: the month-end order predicts the rating six months later
  at `0.79` (Pearson on log-ratings, 95% bootstrap CI `[0.70, 0.86]`), so
  `R = 1 - 0.79^2 ~ 0.38` (CI `[0.26, 0.51]`), an upper bound on the
  manufactured share. `R` is computed from a Pearson correlation because it is a
  variance share; rank correlations are printed alongside and agree to within
  `0.05`. `--survivorship` sweeps the convergence filter over 1, 5, 10, 20 and
  40 later games and returns `R = 0.45, 0.35, 0.35, 0.38, 0.33`, with no
  monotone trend.

`run_all.sh --lichess` passes `--bootstrap 2000 --survivorship`.
